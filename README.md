# genOferta — AI-агент объединения изменений в Оферту «Удобный доступ»

Веб-приложение для задачи из требований Банка: несколько согласованных
инициатив по изменению **публичной оферты «Удобный доступ»** (Приложение 7 к
АФД 4218) собираются в одну дату в **два файла**:

1. **Объединённый файл с вносимыми изменениями** — все правки из нескольких
   документов «Изменения», выстроенные **в порядке следования пунктов Оферты**.
2. **Актуальный текст Оферты** с внесёнными изменениями, **выделенными цветом**
   (и/или в режиме рецензирования Word).

Так снимается необходимость каждый раз дорабатывать шаблон Оферты и проходить
ПСИ по каждой мелкой правке.

## Как это устроено: алгоритм + ИИ (гибрид)

Ключевое архитектурное решение — **разделение ролей**:

| Этап | Исполнитель | Почему так |
|------|-------------|-----------|
| Понять формулировку правки («что, куда, какой якорь, какой текст») | **ИИ** (OpenRouter) | Инструкции написаны живым юридическим языком, формулировки плавают, встречаются опечатки. Regex здесь хрупок. |
| Применить правку к тексту Оферты (вставка, замена, строки таблицы, выделение) | **Детерминированный движок** (OOXML) | Юридический текст на сотни КБ **нельзя** отдавать модели на переписывание. ИИ указывает только координаты — текст меняет код, байт-в-байт. |
| Слить и упорядочить правки по структуре Оферты | Детерминированно | Позиция цели в Оферте задаёт порядок. |

ИИ здесь — **парсер намерения**, а не переписчик документа. Перед применением
оператор **подтверждает** распознанные операции на экране проверки.

Подробное обоснование «алгоритм vs ИИ» — в [docs/АРХИТЕКТУРА.md](docs/АРХИТЕКТУРА.md).

## Режимы разбора (выбираются в интерфейсе)

- **Авто** (по умолчанию) — ИИ, если задан ключ и доступен OpenRouter; иначе
  автоматически детерминированный алгоритм.
- **ИИ (OpenRouter)** — принудительно ИИ; при недоступности сети/ключа
  прозрачно срабатывает алгоритм-fallback (с пометкой в интерфейсе).
- **Только алгоритм** — детерминированный парсер по шаблонам, **без ИИ и без
  сети**. Гарантированно работает офлайн; годится для типовых формулировок.

Модель OpenRouter можно указать в интерфейсе (поле «Модель») или через
`OPENROUTER_MODEL`. База API — `OPENROUTER_BASE_URL` (по умолчанию OpenRouter).

## Поддерживаемые типы правок

- `Сноску N после слов «…» дополнить: «…»` — вставка в сноску (нумерация сносок
  вычисляется по порядку ссылок; при сбое нумерации — поиск по содержимому);
- `Пункт X … после слов «…» дополнить словами: «…»` — вставка в тело пункта
  (с флагом «перенумерация сносок»);
- `п. X изложить в следующей редакции: «…»` — замена пункта/термина/пункта
  приложения (поиск абзаца по началу редакции, т.к. номера автоматические);
- `Дополнить таблицу … строками X–Y` — добавление строк в таблицу приложения.

## Стек

- **Next.js 16** (App Router, TypeScript) + **Tailwind CSS v4**
- Движок правок — свой, на **OOXML** (jszip), серверный (`lib/`)
- **OpenRouter** — разбор инструкций (серверный route, ключ не уходит в браузер)
- Хостинг — **Vercel**

## Локальный запуск

```bash
npm install
cp .env.example .env       # заполнить OPENROUTER_API_KEY (или оставить пустым — оффлайн-режим)
npm run dev                # http://localhost:3000
```

Без ключа OpenRouter приложение работает в **оффлайн-режиме**: инструкции
разбирает встроенный детерминированный парсер по шаблонам (годится для типовых
формулировок и демонстрации).

## Проверка движка на образцах (без UI, без ИИ)

```bash
npm run engine:demo
```

Прогоняет реальные образцы из `fixtures/` (Оферта + два документа «Изменения»),
печатает распознанные операции, порядок применения и отчёт, и складывает
результат в `tmp-out/`.

## Переменные окружения

| Переменная | Назначение |
|-----------|-----------|
| `OPENROUTER_API_KEY` | Ключ OpenRouter. Пусто → оффлайн-режим. |
| `OPENROUTER_MODEL` | Модель (по умолчанию бесплатная `deepseek/deepseek-chat-v3.1:free`). |
| `GENOFERTA_OFFLINE` | `1`/`true` — принудительно без ИИ. |

## Структура

```
app/
  page.tsx            экран: загрузка → проверка → скачивание
  api/parse/route.ts  разбор документов «Изменения» → операции
  api/build/route.ts  применение операций → два docx
lib/
  ooxml.ts            хирургические правки OOXML (вставка после якоря, замена абзаца)
  offer-index.ts      сноски: видимый № ↔ id, поиск по содержимому
  apply.ts            применение операций к Оферте (цвет / рецензирование)
  combined.ts         генерация объединённого файла изменений
  parser/             ИИ (OpenRouter) + оффлайн-парсер + оркестратор
  pipeline.ts         полный конвейер и сортировка по порядку Оферты
fixtures/             образцы документов
scripts/demo.ts       E2E-прогон движка
```

## Ограничения (осознанные, для доработки)

- Замена пункта опирается на совпадение **начала** редакции со старым текстом;
  если правка меняет первые слова — оператор поправит ориентир вручную.
- Точная перенумерация сносок и склейка пунктуации на стыке вставок
  выполняются приближённо и выносятся на подтверждение оператору.
- Реквизиты «шапки» объединённого файла (номер, дата, исполнитель) заполняются
  человеком — генератор формирует содержательную часть.
